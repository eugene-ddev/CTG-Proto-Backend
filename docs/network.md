# Сетевой этап прототипа — план

Цель: прототип (`CTG-Proto`) перестаёт быть офлайн-игрой. Инвентарь, персонажи, награды и серии хранятся в базе
на сервере Nakama; появляются бои с реальными игроками и рейтинг. Новый проект — `F:\Projects\games\CTG-Proto-Backend`.

Статус: **этапы 0–5 готовы, этап 6 — скрипты и конфиги выкладки готовы**; сама выкладка — за Евгением (сервер и домен), см. `CTG-Proto-Backend/README.md → Выкладка на сервер`; не сделано ограничение частоты запросов. Есть отложенный вопрос — раздел «Отложенные вопросы». Версия прототипа: сетевые этапы выходили как 1.0.0–1.5.0, затем номер возвращён к 0.x — текущая **0.1.0**.
Последняя офлайн-версия — 0.0.108, коммит `b2f970e` в `CTG-Proto` (репозиторий создан 14.11.2026).

## Что есть сейчас

- `CTG-Proto/src/core` — вся логика игры чистыми функциями `PlayerState → PlayerState` без Phaser и без браузера
  (сборка, снаряжение, рюкзак, прокачка, серия арены, лут, бой). Бой детерминирован: один seed — один исход и лог.
  Состояние — один объект, сейчас в localStorage.
- `CTG-Backend` — бэкенд Unity-клиента: Nakama 3.32 + Postgres, TypeScript-рантайм (rollup → `build/main.js`),
  `StorageService`, RPC по доменам, хук `initPlayer` после `authenticateDevice`, серия арены
  (`Matches` / `Combats`), откат лута при поражении. Результат боя присылает клиент.

## Требования (Евгений, 14.11.2026)

1. Бэкенд на Nakama по примеру имеющегося; награды, инвентарь и прочее — в базе.
2. Два вида серий:
   - с ботами, как сейчас; после поражения лут **не теряется**;
   - с реальными игроками: соперник выбирается из списка, бой идёт с его активным персонажем;
     победил — получаю награду, проиграл — награда уходит сопернику; при поражении лут **теряется**.
3. Лидерборд: рейтинг зависит от побед и поражений и от силы побеждённого соперника.
4. При выборе соперника видно, сколько рейтинга получу за победу и сколько потеряю при поражении.
5. План — по этапам; всё фиксируется в документации.

## Предлагаемая архитектура

- **Тот же стек, что в `CTG-Backend`**: Nakama 3.32 + Postgres в Docker, TypeScript-рантайм, rollup, RPC по доменам,
  `withValidation`, логирование до и после действия, вход через `authenticateDevice` + хук создания игрока.
- **Общая логика с прототипом.** Сервер исполняет тот же `core`, что и клиент: RPC = «действие» (собрать, надеть,
  выпить зелье, начать серию), сервер применяет его к состоянию игрока из базы и возвращает новое состояние.
  Правила не пишутся второй раз и не расходятся. `core` попадает в бэкенд скриптом синхронизации
  (`npm run sync-core`: копия `CTG-Proto/src/core` и `src/data` в `src/shared`, с проверкой расхождения).
- **Бой считает сервер.** Клиент просит «начать бой», сервер считает его по seed и отдаёт лог событий; клиент
  только проигрывает лог (он уже так устроен). Результат подделать нельзя — это обязательно для PvP и рейтинга.
- **Хранение.** У каждого игрока три записи: `player/state` — всё его состояние одним документом (кубы,
  инвентарь, персонажи, чертежи, серия; меняет только он сам своими действиями); `arena/profile` — рейтинг, счёт
  и журнал нападений (меняют и чужие бои); `fighter/active` — снимок активного бойца (читают все). Плюс лидерборд
  Nakama `arena_rating`.
- **PvP асинхронный.** Бой идёт со снимком активного бойца соперника (кубы, снаряжение, приоритет атаки);
  соперник в это время может быть не в игре. Итог приходит ему уведомлением и в журнал боёв.
- **Рейтинг — Эло.** Старт 1000, K = 32, ожидание `E = 1 / (1 + 10^((Rсоперника − Rмой) / 400))`,
  победа `+K·(1 − E)`, поражение `−K·E`. Победа над сильным даёт больше, поражение от слабого отнимает больше —
  это и есть «соотношение побед и сила соперника». Обе цифры считаются до боя и показываются в списке соперников.

## Допущения (поправь, если не так)

- Вход без пароля: device id + имя (как `authenticateDevice` в `CTG-Backend`). Почта и пароль — позже.
- Локальные сейвы 0.0.x на сервер не переносятся: все начинают со стартового набора.
- Офлайн-режим из игры убирается; тесты и симулятор баланса (`npm run sim`) работают без сервера, как раньше.
- Серия с игроками — 3 боя, соперник на каждый бой выбирается из списка; повторов нет: поражение заканчивает
  серию, и весь лут, набранный в ней, пропадает.
- Сервер сначала запускается локально в Docker на машине Евгения.

## Решения (Евгений, 14.11.2026)

1. Архитектура — общий `core` и бой на сервере.
2. Лут с игрока — копии: защитник вещей не теряет, бой идёт со снимком его бойца.
3. Нападавший проиграл — защитник получает награду за бой (кубы и дроп); лут нападавшего, набранный в серии,
   пропадает и защитнику не переходит. Размер награды защитнику — определить на этапе 4.
4. Рейтинг защитника меняется симметрично (обычное Эло): сколько получил один, столько потерял другой.

## Отложенные вопросы

1. **Что именно теряется при поражении** (Евгений 14.11.2026: «запиши на потом»). Требование: с ботами лут не
   теряется, с игроками — теряется. Сделано пока так (переключается в `arena.json → loss`):

   набранное за серию или вместе с оружием и рюкзаком?
