# Игровые механики

## Статы персонажа

Персонаж состоит из кубов — каждый куб добавляет очки статистики.

### Категории персонажей

Категория определяется по усреднённому количеству кубов в чертеже:

| Категория | Кубов в категории |
| --------- | ----------------- |
| 1         | 20                |
| 2         | 30                |
| 3         | 40                |
| 4         | 50                |
| 5         | 60                |
| 6         | 70                |
| 7         | 80                |
| 8         | 90                |
| 9         | 100               |

### Формула очков за блок

```
Очки за блок = Кол-во блоков в категории / Кол-во блоков в чертеже
```

**Пример:** персонаж из 25 кубов → 20 / 25 = **0.8 очка за куб**

Это обеспечивает равенство персонажей по статам внутри одной категории.

### Характеристики

| Стата        | Эффект                                                    |
| ------------ | --------------------------------------------------------- |
| Сила         | Множитель урона для силового оружия + вклад в шанс крита  |
| Ловкость     | Множитель урона для ловкостного оружия + вклад в шанс уворота |
| Броня        | Множитель статы щита                                      |
| Выносливость | Максимальное количество выносливости                      |
| Интеллект    | Максимальное количество маны + множитель статов артефакта |
| Удача        | Шанс критического удара + шанс уворота                    |

### Формулы крита и уворота

```
Крит   = min(0.75, 0.10 + (Удача + Сила/2)     / (Удача + Сила/2     + 50))
Уворот = min(0.75, 0.05 + (Удача + Ловкость/2) / (Удача + Ловкость/2 + 50))
```

- **База** — 10% для крита, 5% для уворота.
- **Удача** — основной вклад в обе формулы (полный вес).
- **Сила / Ловкость** — половинный вклад в крит / уворот соответственно.
- **50** — константа насыщения: при сумме вкладов = 50 даём +50% к базе (diminishing returns).
- **Кап 75%** — максимально достижимое значение, чтобы исключить гарантированный исход.

### Случайность — марбл-бэг

Любой шанс в игре разыгрывается не чистым рандомом, а марбл-бэгом (прототип 0.0.34, `battle-rework.md`):

- в мешке 10 шариков (`bagSize`), выигрышных — шанс × 10; шарики тянутся без возврата, пустой мешок наполняется заново
  по текущему шансу;
- шанс 10% — ровно 1 срабатывание на каждые 10 попыток; дробная часть переносится в следующий мешок
  (13.7% → 1, 1, 2, 1 … на мешок), поэтому в долгую шанс точный;
- у каждого бойца свои мешки на бой: крит (его удары), уворот (удары по нему), распространение горения (по нему);
- лимит «не больше 2 срабатываний подряд» больше не нужен — мешок его заменяет;
- вне боя (прототип 0.0.39) — тоже мешки, которые хранятся в сейве: награда за серию (пергамент — ровно 1 из 10 наград,
  камни 1–5 — каждое число по разу за 5 выпадений) и все броски генерации ботов (выбор из вариантов — без повторов,
  пока не выпадут все).

### Пороги стат

Когда в бою разбито больше половины кубов статы (кубы, разбитые до боя, тоже считаются), её функция отключается
до конца боя (прототип 0.0.35, `combat.json → statThresholds`):

| Стата        | Что отключается                                   |
| ------------ | ------------------------------------------------- |
| Сила         | Урон оружия на Силе ×0.6                          |
| Ловкость     | Уворот — 0                                        |
| Удача        | Крит — 0                                          |
| Выносливость | Порога нет — максимум стамины и так падает на 1 с каждым кубом (0.0.37) |
| Интеллект    | Артефакты не активируются                         |
| Броня        | Порога нет — поглощение и так падает с каждым кубом |

Пример: у бойца 13 кубов Ловкости — уворот пропадает на 7-м разбитом.

### Цель удара — фокус атаки

Прототип 0.0.36, `battle-rework.md`:

- бить можно только передний живой куб столбика — перёд модели смотрит на противника (ось +Z);
- главная цель — первая стата в приоритете атакующего, у которой есть живые кубы;
- фокус атаки идёт по столбику, где до куба главной цели меньше всего живых кубов спереди; при равенстве — тот, чей передний куб
  выше в приоритете, дальше фиксированный порядок столбиков;
- остаток урона сверх прочности куба (10) уходит в следующий куб по фокусу атаки; остаток от горения и яда пропадает;
- приоритет больше не даёт множителя урона;
- все статы противника видны до боя; на экране «Новый противник» золотая полоса показывает весь путь фокуса атаки —
  порядок, в котором будут разбиты кубы противника при текущем приоритете.

### Схемы ударов оружия

Прототип 0.0.37: куда уходит урон сверх прочности куба, решает оружие.

| Схема         | Оружие        | Остаток урона                                                 |
| ------------- | ------------- | ------------------------------------------------------------- |
| Точный        | кинжал, нож   | пропадает; броня действует наполовину                         |
| Рубящий       | меч           | поровну передним кубам соседних столбиков по ряду, если вплотную |
| Колющий       | копьё         | в кубы в 1–2 клетках позади цели; пустоту внутри проходит, дальше не достаёт |
| Раскалывающий | топор         | поровну: куб вплотную позади и вплотную сбоку                 |
| Дробящий      | булава, молот | поровну: крест вплотную к цели и куб вплотную позади          |
| Сквозной      | кулак         | в следующий куб по фокусу атаки                               |

Кинжал бьёт 2 раза за ход: у каждого удара свой крит, уворот и цель; стамина и кулдаун — один раз.

Соседи — по геометрии (0.0.40): «вплотную сбоку» — передний куб соседнего столбика, отличающийся по глубине не больше
чем на 1 клетку; «вплотную позади» — соседняя клетка за целью. Через пустоту остаток не перескакивает (кроме копья
в пределах своих 2 клеток).

### Раскладка стат по кубам

Прототип 0.0.38. Бьют спереди, поэтому важно, где лежит каждая стата:

- ручная сборка — игрок ставит кубы по одному выбранной статой; готового персонажа можно перекрасить (1 куб за замену);
- автосборка раскладывает оставшиеся кубы слоями спереди назад: Броня → Выносливость → Удача → Сила → Ловкость →
  Интеллект (`combat.json → layout.autoBuild`);
- боты — слоями по одному из вариантов `layout.bots`; приоритет атаки бота — под сборку игрока: сначала стата его
  оружия, дальше статы от самых мелких к глубоким;
- в сборке, у персонажа и на экране противника золотой треугольник у пола показывает, с какой стороны бьют.

**Примеры (крит):**

| Удача | Сила | Расчёт                             | Шанс крита           |
| ----- | ---- | ---------------------------------- | -------------------- |
| 0     | 0    | 0.10 + 0/(0+50)                    | **10%**              |
| 10    | 20   | 0.10 + 20/(20+50) = 0.10 + 0.286   | **~39%**             |
| 50    | 100  | 0.10 + 100/(100+50) = 0.10 + 0.667 | **~77% → 75%** (кап) |

**Примеры (уворот):**

| Удача | Ловкость | Расчёт                             | Шанс уворота |
| ----- | -------- | ---------------------------------- | ------------ |
| 0     | 0        | 0.05 + 0/(0+50)                    | **5%**       |
| 10    | 20       | 0.05 + 20/(20+50) = 0.05 + 0.286   | **~34%**     |
| 50    | 100      | 0.05 + 100/(100+50) = 0.05 + 0.667 | **~72%**     |

## Снаряжение

Каждый вид снаряжения имеет **способность**, содержащую информацию об уроне, таймингах и условиях использования.

### Характеристики способностей

- **Основная характеристика** (урон, защита, кол-во HP при лечении) — зависит от уровня снаряжения и скалирующей статы.
- **Сопутствующая характеристика** (скорость анимации, время отката, расход выносливости/маны) — зависит от вставленных камней.

### Генерация снаряжения

При генерации используется относительный коэффициент (+/−) к минимальному и максимальному значению характеристик.

### Необходимый уровень статы

У некоторого снаряжения есть требование к минимальному значению скалирующей статы для возможности использования.

### Уровень снаряжения

> Прототип 0.0.48 (этап 8 доработки боя, `battle-rework.md`): у оружия **3 уровня**, уровень даёт не урон, а
> свойство схемы удара. Урон зависит только от статы. Ячейки камней от уровня не зависят.

- Улучшает имеющееся оружие; прокачивать можно и в инвентаре, и надетое (кроме бойца в серии арены)
- Цена — **точильные камни**: ур. 2 — 10, ур. 3 — 25
- Свойства уровней:

| Оружие | Ур. 2                                     | Ур. 3                                         |
| ------ | ----------------------------------------- | --------------------------------------------- |
| Кинжал | броня не действует                        | + пробивает на 1 клетку вглубь                |
| Нож    | броня не действует                        | крит ×3 вместо ×2                             |
| Меч    | остаток ещё и соседям сверху/снизу        | соседи получают остаток целиком, без деления  |
| Копьё  | дальность пробития 3 клетки               | дальность 4, броня действует наполовину       |
| Топор  | вбок в обе стороны                        | + вторая клетка позади                        |
| Булава | 20% оглушить (пропуск хода, марбл-бэг)    | 35% оглушить                                  |
| Молот  | крест + диагонали (3×3 на передней грани) | + 2 клетки позади                             |

- **Ячейки для камней** создаёт предмет «Ювелирный набор» (1 набор — 1 ячейка, максимум 3 на оружие). Набор
  выпадает в награде за пройденную серию арены (~10%)
- Боты: уровень оружия 1–3, не выше, чем у игрока; ячеек 0…(уровень − 1)

### Скалирующая статистика по типу оружия

| Стата     | Оружие                          |
| --------- | ------------------------------- |
| Ловкость  | Кинжал, Меч, Лук, Копьё, Рапира |
| Сила      | Булава, Топор, Молот            |
| Интеллект | Посох, Гримуар                  |
| Броня     | Щит                             |

### Формула урона

> В прототипе с 0.0.48 множитель уровня не применяется (уровень = 1): уровень оружия даёт свойства, а не урон.

```
Урон = (Базовый_урон + Стата * С) * (1 + Уровень * У)
```

- **С** — коэффициент статы (напр. `2`) — ощутимый скачок силы за "мастерство"
- **У** — множитель уровня (напр. `0.01`) — плавный процентный при апгрейде

**Примеры (С=5, У=0.01, Базовый_урон=100):**

| Уровень меча | Ловкость | Расчёт                              | Урон    |
| ------------ | ---- | ----------------------------------- | ------- |
| 10           | 50   | (100 + 50) × (1 + 0.50) = 150 × 1.5 | **225** |
| 20           | 50   | (100 + 100) × 1.5 = 200 × 1.5       | **300** |
| 10           | 100  | 150 × (1 + 1.00) = 150 × 2.0        | **300** |

## Эффекты

Эффект — это сущность, которую **способность накладывает** при срабатывании (отравленное оружие, купол щита, дебафф слабости). Эффекты лежат в общем **каталоге** — их параметры, иконку и описание можно редактировать централизованно, не трогая способности. Математику (урон по времени, тики, поглощение щитом) считает **клиент**, как и весь бой; сервер хранит только данные эффектов.

### Куда вешается эффект

| Источник способности | Куда применяются эффекты |
| -------------------- | ------------------------ |
| Атакующая (`Attack` / `ProjectileAttack`) | на **блок цели** при попадании — отравленное/огненное оружие |
| Self-cast (например, щит артефакта) | на **владельца** способности |
| Дебаффы (слабость) | по той же логике: атака → цель, self-cast → себя |

### Типы эффектов

Текущий каталог — 4 вида (дискриминируются по `kind`):

| Тип | Назначение | Параметры |
| --- | ---------- | --------- |
| **Отравление** (Poison) | периодический урон по блоку | длительность, интервал тика, урон за тик |
| **Горение** (Burn) | урон по времени + распространение | длительность, интервал, урон за тик, шанс распространения на живого соседа за тик |
| **Щит** (Shield) | купол, поглощающий физические атаки | длительность |
| **Слабость** (Weakness) | снижение статы цели | длительность, стата, множитель (`0.8` = −20%) |

**Единицы.** Длительность и интервал — в секундах; множитель — доля (`0.8`); шанс распространения — `0..1`.

### Связь со способностями

Каждая способность несёт список своих эффектов. У оружия/артефакта он задаётся в данных способности; если список пуст — способность работает как раньше, без эффектов.

## Камни

В слоты снаряжения (1–3) можно вставлять камни.

- Модифицируют **сопутствующие характеристики** относительными значениями (без уровня — одинаково эффективны на любом уровне снаряжения)
- Могут добавлять **стихийный эффект** на оружие: огонь, лёд, яд и др. (см. [Эффекты](#эффекты))

## Артефакты

Артефакт — **магический предмет** с особым свойством. Экипируется в отдельный слот персонажа (`SlotType.Artifact`) — как оружие в руку. Каждый артефакт:

- **расходует ману** при активации (пул маны зависит от Интеллекта, см. [Характеристики](#характеристики));
- имеет собственную **скалирующую стату**, усиливающую его эффект;
- имеет **уровень предмета** (как у оружия) — улучшается прокачкой.

Активируется **во время боя**; сам эффект (купол, тайминги) считает клиент по данным способности артефакта. Артефакты **не ограничены щитом** — каждый несёт свою способность с собственным набором эффектов (см. [Эффекты](#эффекты)).

### Артефакт магического щита

Защитный артефакт (отдельных «щитов»-предметов нет — их роль выполняет этот артефакт). Ставит на короткое время **купол**, поглощающий **физические** атаки.

| Параметр              | Значение                                          |
| --------------------- | ------------------------------------------------- |
| Эффект                | Купол, защищающий от **физических** атак           |
| Базовая длительность  | 1 секунда                                          |
| Скалирующая стата     | **Броня** — увеличивает длительность купола        |
| Расход маны           | 10                                                 |
| Слот                  | Артефакт (`SlotType.Artifact`)                     |

- Купол реализован как **эффект Щит** (см. [Эффекты](#эффекты)) — базовая длительность является параметром этого эффекта.
- **Стартовая выдача.** Новый игрок получает «Артефакт магического щита» в инвентарь. Существующим игрокам он доначисляется ретроактивно (миграция).

## Расходуемые предметы

Расходуемые предметы (консюмаблы) — **одноразовые** предметы, которые складываются в стаки (до **5** штук в стаке) и тратятся по одной штуке за использование. Применяются **во время боя** из подсумка (см. [Подсумок и рюкзак](#подсумок-и-рюкзак)). Когда стак опустошается, предмет исчезает из контейнера.

### Зелья восстановления

Зелье восстановления возвращает разрушенные **кубы** персонажа того же цвета прямо в бою. Цвет зелья соответствует цвету куба (и связанной с ним стате) — так же, как у ресурсных кубов:

| Цвет зелья | Куб / Стата   |
| ---------- | ------------- |
| Красный    | Сила          |
| Чёрный     | Броня         |
| Жёлтый     | Ловкость      |
| Зелёный    | Выносливость  |
| Синий      | Интеллект     |
| Оранжевый  | Удача         |

У каждого цвета — два тира, отличающихся силой эффекта:

| Тир     | Восстанавливает | Пример названия                  |
| ------- | --------------- | -------------------------------- |
| Пузырёк | 1 куб           | «Красный пузырек восстановления» |
| Флакон  | 3 куба          | «Синий флакон восстановления»    |

- Всего **12 зелий** — 6 цветов × 2 тира.
- Максимум в стаке — **5** штук.
- **Стартовый набор.** Новый игрок получает по полному стаку (5 штук) пузырьков **красного**, **чёрного** и **жёлтого** цвета.

## Ресурсы

### Кубы

- Используются для сборки персонажей и снаряжения
- После установки в чертёж извлечь нельзя
- При разрушении персонажа остаются **осколки кубов**
- Осколки можно переработать обратно в целые кубы

### Осколки кубов

- Основной ресурс который будет падать с персонажей и ботов

**Пример переработки:**

```
1 куб = 6 осколков + 1 смола
```

## Инвентарь

Инвентарь хранит ссылки на снаряжение, при экипировке на персонажа пропадает из инвентаря

### Подсумок и рюкзак

Подсумок и рюкзак — это **экипировка**, которая надевается на персонажа в специальные слоты (`SlotType.Pouch`, `SlotType.Rucksack`). У этих слотов `position: null` — они не имеют 3D-позиции и не отображаются на меше персонажа.

- **Подсумок** — 3 слота. Предметы внутри можно использовать во время боя. Перемещение предмета из инвентаря в подсумок удаляет его из инвентаря (как при обычной экипировке).
- **Рюкзак** — 6 слотов. Временное хранилище лута, накопленного за серию боёв на арене (см. [Арена и лут](#арена-и-лут)).

Сами подсумок и рюкзак — это записи в `Equipment`-коллекции. Их содержимое (`items[]`) хранится **внутри** записи экипировки и переезжает вместе с ней при экипировке/снятии.

## Арена и лут

Арена — это серия боёв, в которую игрок заходит со своей экипировкой. Между боями он принимает решение: забрать накопленный лут или продолжить и рискнуть им ради более ценной добычи.

### Снаряжение на входе

На арену игрок заходит с:

- **Оружие** — то, что надето на персонажа
- **Подсумок** — до 3 предметов экипировки (см. [Подсумок игрока](#подсумок-игрока))

Всё это считается **снаряжением сессии** — то, чем игрок будет рисковать в боях.

### Исход боя

| Исход                  | Что происходит со снаряжением игрока | Что выпадает с оппонента                                 |
| ---------------------- | ------------------------------------ | -------------------------------------------------------- |
| **Победа (обычный)**   | Сохраняется                          | Дроп: оружие или экипировка оппонента → в **рюкзак**     |
| **Победа (бой с тенью)** | Сохраняется                        | Дроп идёт игроку, оппонент-«тень» **ничего не теряет**   |
| **Поражение**          | Текущее оружие + содержимое подсумка **пропадают** | —                                            |

> **Бой с тенью** — режим, где оппонент является копией реального игрока (или ботом-«тенью»), и его настоящий инвентарь не затрагивается.

### Восстановление разбитых кубов

Разбитые кубы бойца восстанавливаются со временем вне арены — в лобби и при закрытой игре (догоняются при загрузке):
по одному кубу за интервал (`LOBBY_REGEN_MS`, в прототипе 30 с). Пока идёт серия арены (с экрана «Новый противник»
до выхода из серии), кубы сами не чинятся — только зелья восстановления из рюкзака; отсчёт начинается с выхода.
В прототипе (0.0.41) это написано красным — «не чинятся, пока на арене» — в меню, на экране персонажа и в карточке
бойца на экране противника.

### Рюкзак

Рюкзак — это **временное** хранилище лута, накопленного за серию боёв на арене.

- Доступ к рюкзаку открывается **только между боями** (в конце текущего боя)
- В бою рюкзак недоступен — нельзя достать предмет посреди драки
- Из рюкзака можно:
  - **Сменить оружие** — текущее оружие отправляется в рюкзак, новое — на персонажа
  - **Переложить экипировку в подсумок** — если в подсумке есть свободный слот или игрок решает заменить предмет
- Содержимое рюкзака **тоже считается под риском**: при поражении пропадает вместе с экипировкой сессии

### Выбор между боями

После каждой победы игрок принимает решение:

| Решение         | Эффект                                                                                  |
| --------------- | --------------------------------------------------------------------------------------- |
| **Выйти**       | Весь лут из рюкзака + текущая экипировка сохраняются в постоянный инвентарь — сейв       |
| **Продолжить** | Следующий бой; в случае поражения теряется **всё** (оружие, подсумок, рюкзак) — риск    |

Это создаёт классический трейдофф **press-your-luck**: чем дольше игрок остаётся на арене, тем ценнее потенциальный лут и тем выше цена ошибки.

## Награды

Награда — предмет прогрессии, который сервер выдаёт игроку (за бой на арене, ежедневный вход и т.п.). Содержит **набор предметов** и опционально **валюту**.

### Состав

- Каждая награда — это список **«предмет → количество»** плюс опциональная валюта (монеты, алмазы, очки прокачки).
- Предметом может быть снаряжение, расходник или ресурс.
- **Экипировка** выдаётся поштучно — каждая единица становится отдельным предметом (2 меча → 2 предмета).
- **Стэкуемые** (ресурсы, расходники) выдаются стаком на указанное количество (50 ресурса → один стак на 50).

### Уведомление

При создании награды игрок получает **уведомление** с её составом (что внутри). Уведомление **висит, пока награду не заберут** — оно и служит «входом» к получению.

### Получение

Игрок забирает награду вручную. Перед выдачей сервер проверяет, что в инвентаре хватает места:

| Условие | Результат |
| ------- | --------- |
| Слотов не хватает | Награда **не выдаётся**, остаётся ждать (уведомление не исчезает) |
| Места достаточно | Предметы попадают в инвентарь, валюта — в кошелёк; награда и уведомление исчезают |
